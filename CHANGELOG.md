# Changelog

## 2026-11-13
- **Nhà cung cấp** and **Khách hàng** moved to MVP: new `Presentation.Partners` presenters (`SupplierListPresenter`, `SupplierEditPresenter`, `CustomerListPresenter`, `CustomerEditPresenter`) hold permissions, confirmations, toasts and validation; `SupplierListScreen`, `CustomerListScreen` and their edit dialogs are now passive views resolved through DI.
- `IView.Confirm` lets presenters ask yes/no questions (stop trading, deactivate a customer); new `Mvp.FormInput` with `Optional` (trim, blank → null) and `FirstError` (first failing property + message).
- Improvements: a failed save now puts the cursor in the offending field (e.g. Mã số thuế, Số điện thoại, Email) instead of leaving focus on the button; stopping/resuming a supplier now confirms with a toast ("Đã ngừng giao dịch với …").
- 41 new presenter tests (Domain 149, Application 486, Infrastructure 63, UI.Controls 427, Presentation 70 – all passing).

## 2026-11-12
- **MVP foundation**: new `GroceryPOS.Presentation` project (net8.0, no WinForms) with `Mvp.Presenter<TView>` (single view attach, one DI scope per action via `UseAsync`/`UseScopeAsync`, closed-view checks after awaits), `Mvp.IView` (warnings and toasts) and `AddPresentation()` registering presenters as transient.
- **Danh mục** is the first screen on MVP: `CategoryListPresenter` (permission, load with error toast, add/edit flow, stop/resume with confirmation toasts, guarded against a screen closed mid-action) and `CategoryEditPresenter` (title and initial values, blank description → null, FluentValidation before saving, focus on the name field) – `CategoryListScreen` and `CategoryEditForm` are now passive views. `MainForm` receives the service provider to resolve presenters.
- **CI**: GitHub Actions workflow – Linux build + tests on every push/PR, then a Windows job running `build/publish.ps1` (Inno Setup via Chocolatey) that uploads the installer, the portable zip and test results.
- New `tests/GroceryPOS.Presentation.Tests` with fake views and a real DI container (29 tests – Domain 149, Application 486, Infrastructure 63, UI.Controls 427, Presentation 29 – all passing).

## 2026-11-11
- **Publishing & installer**: publish profiles `win-x64` (one self-contained `GroceryPOS.exe`, ~75 MB, no runtime to install) and `win-x64-framework` (~27 MB, needs .NET Desktop Runtime 8.0); Inno Setup script `installer/GroceryPOS.iss` (Program Files or per-user install, Start menu/desktop shortcuts, asks to close the running app before an upgrade, runtime check for the framework build, keeps the shop's data on uninstall); `build/publish.ps1` (tests → publish → portable zip → installer) and `build/publish.sh` for Linux CI. Version 0.9.0 from `Directory.Build.props`, new basket app icon, Release builds embed symbols.
- **Data folder** (`Infrastructure.Hosting.AppDataLocation`): the database, logs, backups, parked orders and UI preferences now always live outside the program folder – `%LocalAppData%\GroceryPOS` by default, `data\` beside the exe when `portable.txt` is present, or `GROCERYPOS_DATA` / `Paths:DataDirectory`. Optional `appsettings.local.json` there overrides the shipped settings and survives upgrades. Fix: the SQLite database used to be created in the working directory (Program Files when installed); an existing `grocerypos.db` beside the exe is copied over once at start-up.
- Only one copy runs per data folder – starting it again brings the open window to the front; the restart after a database restore waits for the old copy to exit. Start-up failures (unwritable folder, broken settings) now show a clear message instead of crashing.
- **Thông tin phần mềm** (user menu): version, runtime and every path (program, data, database, logs, backups, local settings), buttons to open the data/log folders and to copy the details for support, SQL Server passwords masked (`SupportInfo`).
- 10 new tests (Domain 149, Application 486, Infrastructure 63, UI.Controls 427 – all passing).
